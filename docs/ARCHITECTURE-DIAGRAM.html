Messaging: Dapr sidecars + Kafka

Dapr sidecars

A small helper container next to each service. The service just says "publish" or "subscribe"; Dapr talks to Kafka.

Kafka (Strimzi)

The message bus. Services never call each other directly for events.

Microservices (each reacts to events on its own)

Notification :8002

Listens to reminders. Sends reminder notifications.

Recurring Task :8003

Listens to task-events. When a recurring task is completed, it creates the next one through the backend.

Audit :8004

Listens to task-events. Writes a history of what happened.

WebSocket :8005

Watching the system (optional in the demo)

Prometheus

Collects numbers (metrics) from every pod: CPU, memory, requests per second, errors. It stores them over time.

Grafana

Draws those numbers as charts and dashboards, so you can see health at a glance.

Kubernetes Dashboard

A web view of the cluster itself: which pods run, which are healthy, their logs.

In plain words

  • Kubernetes: the manager. It runs every part as a pod, restarts anything that crashes, and routes traffic. It also acts as the front door (the gateway) for the app.
  • Kafka: a post office. The backend drops a message; interested services pick it up.
  • Dapr: the postal clerk next to each service, so code stays simple.
  • Prometheus: collects and stores the numbers.
  • Grafana: turns the numbers into charts.
  • MCP: a standard way to give an AI agent safe tools.
